# Agent 技术演进史

> Agent 并不是突然随着 ChatGPT 出现的新概念。它经历了符号主义、统计学习、深度学习、基础模型和工具型智能体五个阶段。理解这条主线，才能分清哪些是新能力，哪些只是旧思想的新实现。

## 学习目标

- 理解 Agent 技术发展的五个阶段。
- 说清专家系统、强化学习、LLM Agent 的差异。
- 理解 ReAct、Tool Calling、Multi-Agent 为什么会出现。
- 能从历史规律判断一个 Agent 方案是否只是“套壳”。

## 一条主线：从规则到开放环境决策

```text
手写规则
  -> 从数据学习局部策略
  -> 神经网络学习表示
  -> 基础模型获得通用语言能力
  -> 模型连接工具、记忆和环境
```

Agent 技术始终在解决同一个问题：

> 一个系统如何感知当前状态，根据目标选择动作，并利用环境反馈继续决策？

变化的是决策策略从哪里来。

| 阶段 | 决策来源 | 优点 | 主要限制 |
|:---|:---|:---|:---|
| 符号主义 | 人工规则、逻辑推理 | 可解释、可验证 | 规则维护困难 |
| 统计学习 | 数据与概率模型 | 能处理不确定性 | 泛化范围有限 |
| 深度学习 | 神经网络表示 | 感知能力强 | 缺少长期规划 |
| 基础模型 | 大规模预训练 | 通用语言与知识能力 | 不能天然行动 |
| LLM Agent | LLM + 工具 + 状态 +反馈 | 可处理开放任务 | 稳定性、安全、成本 |

## 第一阶段：符号主义与专家系统

1950 年代到 1980 年代，人工智能研究主要依赖符号、逻辑和搜索。

典型系统将知识写成规则：

```text
IF 用户发烧 AND 咳嗽
THEN 考虑呼吸道感染
```

### 核心技术

- 状态空间搜索：BFS、DFS、A*。
- 逻辑推理：命题逻辑、一阶逻辑。
- 规划：STRIPS、目标栈规划。
- 专家系统：知识库 + 推理引擎。

### 对今天 Agent 的影响

现代 Agent 仍大量使用这些思想：

- `state` 对应状态空间。
- `tool` 对应可执行动作。
- `planner` 对应规划器。
- `guardrail` 对应规则约束。
- `graph workflow` 对应显式状态机。

符号主义的问题不是“规则没用”，而是无法靠人工规则覆盖开放世界。生产系统通常仍需要确定性规则包住概率模型。

## 第二阶段：行为式 Agent 与强化学习

1980 年代后，研究者开始强调 Agent 与环境的持续交互。

强化学习把问题表示为马尔可夫决策过程：

$$
M = (S, A, P, R, \gamma)
$$

- $S$：状态。
- $A$：动作。
- $P$：状态转移。
- $R$：奖励。
- $\gamma$：未来奖励折扣。

目标是学习策略 $\pi(a|s)$，最大化期望累计回报：

$$
J(\pi)=\mathbb{E}_{\pi}\left[\sum_{t=0}^{T}\gamma^t r_t\right]
$$

### 这一阶段的突破

- Agent 不再只执行固定规则，而是通过反馈学习策略。
- 多智能体强化学习开始研究协作、竞争和博弈。
- 机器人、游戏 AI 成为重要实验环境。

### 局限

传统强化学习通常需要明确状态、动作和奖励。现实知识工作任务很难写出完整环境和稳定奖励，因此难以直接迁移到开放文本任务。

## 第三阶段：深度学习与表示革命

2012 年后，深度神经网络显著提升了视觉、语音和自然语言处理能力。

重要变化不是 Agent 结构消失了，而是“感知模块”更强：

```text
图像 -> CNN/ViT -> 结构化观察
文本 -> RNN/Transformer -> 语义表示
观察 + 状态 -> 策略网络 -> 动作
```

深度强化学习进一步把感知和决策结合。DQN、策略梯度、Actor-Critic 等方法使 Agent 能处理高维输入。

但这些系统大多仍局限在单一任务和封闭环境。

## 第四阶段：Transformer 与基础模型

Transformer 通过自注意力机制扩展了序列建模能力。随后出现的预训练语言模型让系统获得：

- 零样本和少样本任务迁移。
- 自然语言指令理解。
- 代码生成与结构化输出。
- 一定程度的分解、推理和自我修正。

LLM 相当于一个通用但不稳定的策略模型：

```text
输入：目标 + 上下文 + 工具描述 + 历史观察
输出：回答或下一步动作
```

单独的 LLM 仍不是完整 Agent，因为它没有可靠的外部行动、持久状态和执行反馈。

## 第五阶段：LLM 驱动 Agent

### ReAct：推理与行动交替

ReAct 将语言推理和工具行动放入同一循环：

```text
判断需要什么信息
  -> 调用搜索工具
  -> 观察搜索结果
  -> 更新判断
  -> 输出答案或继续行动
```

它解决了纯语言模型无法接触实时世界的问题，也让工具轨迹更容易观察。

### Tool Calling：从文本协议到结构化动作

早期 Agent 常让模型输出：

```text
Action: search["query"]
```

现代模型 API 通常支持结构化工具调用：

```json
{
  "name": "search",
  "arguments": {"query": "ReAct paper"}
}
```

这降低了解析错误，但不会自动解决工具误选、参数错误和越权问题。

### Reflection：用反馈修正策略

Reflection 类方法让系统在失败后生成简短复盘，再重新规划。有效反思必须基于可验证反馈，例如测试失败、评分器结果或用户纠正，而不能只是让模型“再想一遍”。

### Multi-Agent：角色分工与上下文隔离

多智能体系统将任务拆给不同角色：

```text
Coordinator
  -> Researcher
  -> Coder
  -> Reviewer
```

它的真实价值通常是：

- 分离上下文和权限。
- 并行执行独立任务。
- 使用不同模型或工具。
- 设置独立审核角色。

如果多个 Agent 只是使用相同模型反复聊天，通常只会增加成本。

## 关键里程碑

| 时间 | 代表事件 | 对 Agent 的意义 |
|:---:|:---|:---|
| 1950s | 图灵测试、早期搜索 | 提出机器智能与问题求解 |
| 1970s-1980s | 专家系统 | 知识库与推理引擎 |
| 1990s | 强化学习体系成熟 | 通过环境反馈学习策略 |
| 2012 | 深度学习突破 | 感知与表示能力提升 |
| 2017 | Transformer | 通用序列建模架构 |
| 2020-2022 | 大规模语言模型 | 通用语言任务迁移 |
| 2022 | ReAct | 推理与工具行动结合 |
| 2023 | AutoGPT、AutoGen 等 | 自主循环与多 Agent 工程探索 |
| 2024 以后 | Agent runtime、MCP、评测体系 | 从 Demo 转向协议、运行时和治理 |

## 历史给工程实践的四点启示

1. **规则不会消失**：高风险边界必须由确定性策略控制。
2. **模型不是系统**：模型能力提升不能替代状态、工具、恢复和评测。
3. **反馈必须可信**：没有环境反馈的“自我反思”可能放大幻觉。
4. **复杂度要有收益**：Multi-Agent 应证明比单 Agent 或 workflow 更好。

## 面试表达

> Agent 技术从符号规则、规划和强化学习一路演进到 LLM 驱动系统。LLM 带来了通用语言策略，但完整 Agent 仍需要工具、状态、反馈、权限和评测。今天可靠的架构不是抛弃传统方法，而是用 workflow 和规则控制确定部分，用模型处理开放决策点。
